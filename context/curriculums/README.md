# Curriculums

Syllabi for this concept coach. The agent reads them when authoring a guide, mini game, or step-by-step session. The app does not serve these files.

Teach a track in the listed order. A later lesson assumes the earlier ones. Take data structures before the algorithms that use those shapes. Design systems and design patterns can start after the first few data-structure lessons.

A lesson becomes a guide. The lesson slug is the content id. Step-by-step coaching is for a choice (which structure, which consistency, which pattern). Quizzes cover the practice lines. The app does not ship a mini game per lesson: each lesson names a different mechanic, and a gallery of one-off games would stay thin.

The system-design lesson about moving work off a request uses the slug `work-queues`. The data-structures lesson keeps `queues`. One join key cannot mean both.

| Track | File | Lessons |
|-------|------|---------|
| Data structures | [data-structures.md](data-structures.md) | Arrays through union-find: cost of each operation and when to pick the shape |
| Algorithms | [algorithms.md](algorithms.md) | Complexity through intervals: search, walk, narrow, and reuse work |
| Design systems | [design-systems.md](design-systems.md) | Interview system design: requirements, data, traffic, and failure |
| Design patterns | [design-patterns.md](design-patterns.md) | Named object structures, the forces that earn them, and when to skip the name |
